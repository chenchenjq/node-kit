# sms-kit 管理端前端开发规范

## 1. 适用范围

本规范用于在 Next.js 宿主应用中实现 `sms-kit` 管理端。`sms-kit` 本身保持 headless，不导出 React 组件、样式或浏览器端 Secret 能力。

默认技术栈：

- Next.js App Router
- TypeScript strict
- Tailwind CSS
- shadcn/ui
- 宿主既有的表单、数据请求、通知和权限方案；如无既有方案，表单使用 React Hook Form 与 Zod

所有调用凭据解析器、阿里云 SDK、PostgreSQL 和管理写操作的代码必须位于 Node.js Runtime 服务端，不支持 Edge Runtime。客户端组件只能用 `import type` 从 `sms-kit/next/types` 获取浏览器安全 DTO；不得导入 `sms-kit/application`、`security`、`postgres`、`aliyun`、`better-auth` 或 `next` 等敏感运行时入口。宿主服务端入口使用 Next.js 的 `server-only` 边界，构建测试必须证明 Client Component 误导入时失败。

租户由宿主认证会话或可信服务端路由上下文决定，客户端不得通过请求体、查询参数或自定义 Header 任意指定 `tenantId`。单租户宿主使用固定默认租户键；本管理端不要求租户选择器。供应商配置、签名和模板是系统级共享资源，发送记录、验证码运行状态、回执健康、任务和统计只显示当前租户数据。

## 2. 信息架构

页面标题为“短信管理”，使用同一页面内的资源标签页：

1. 服务配置
2. 签名
3. 模板
4. 验证码
5. 回执与补查
6. 发送记录
7. 统计

页面标题区始终展示整体状态徽标、最近权限测试时间、最近回执时间、系统当日预算占用、人工熔断状态和当前告警数量。用户无某标签权限时隐藏写操作，但保留必要的只读状态；完全无读取权限时显示明确的无权限页。

## 3. 通用交互规则

- 页面 URL 保存当前标签、页码、筛选和日期范围，刷新与分享后状态可恢复。
- 所有表格提供加载骨架、空状态、错误状态、重试入口和分页。
- 表单字段必须有持久标签、说明、错误文本和错误摘要；不能只依赖 placeholder。
- 写操作在成功后使相关查询失效，并展示可追踪的操作结果，不做乐观假成功。
- 使用服务端返回的 `version` 做乐观锁；冲突时展示“配置已被其他操作修改”，允许重新加载，不静默覆盖。
- 供应商错误转换为面向管理员的说明，并在详情中显示可复制的稳定错误码和 Request ID。
- 服务端不得向客户端回传完整手机号、Secret、OTP、未过滤模板变量和供应商原始载荷。管理员主动输入的测试号码或精确查询号码可以作为一次性 HTTPS 请求字段提交，但客户端不得持久化、缓存、分析或记录，并在操作结束后清除输入状态。
- 危险操作不得只靠颜色表达；按钮文本必须明确具体动作。

## 4. 标签页规范

### 4.1 服务配置

展示字段：供应商、区域、可选端点、AccessKey ID 引用、AccessKey Secret 引用、启用状态、最近测试摘要和版本。端点输入只接受凭据无关的 HTTPS origin（例如 `https://host.example` 或带方括号 IPv6/可选端口），不得接受路径、查询、片段或用户信息；展示和回填保持 API 返回的完整 origin。

主要操作：

- 保存配置。
- 执行无费用的连接与权限测试。
- 打开真实发送测试对话框。
- 启用或停用短信服务。

保存密钥引用后不回显完整引用；只展示 scheme 和脱敏变量名。配置发生变化后，状态回到“待测试”，只有权限测试成功才能启用。真实发送测试对话框必须展示脱敏手机号、签名、模板、变量名、费用提示和确认按钮。

### 4.2 签名

表格列：签名名称、云端类型、云端审核状态、本地启停、最近同步时间和关联模板数。

同步先展示差异预览：新增、状态变化、云端不可用和未选择导入的资源。预览 DTO 必须包含同步 ID、候选 ID、校验和与过期时间；过期或校验冲突时禁止确认并要求重新同步。管理员确认后才更新本地快照。停用有关联启用模板的签名时，展示影响模板数量并要求确认。

### 4.3 模板

表格列：稳定键、云端名称、TemplateCode 脱敏展示、用途、变量、签名、云端状态、本地状态和最近同步时间。

导入流程要求管理员：

1. 选择云端已审核模板。
2. 选择已导入签名。
3. 输入稳定模板键。
4. 指定用途。
5. 检查自动解析的变量集合。
6. 确认导入并决定是否立即启用。

稳定键在模板产生第一条发送记录后不可原地修改；需要更名时导入为新稳定键、迁移调用方，再停用旧模板。尚未使用的稳定键修改需要单独操作并写入审计。

### 4.4 验证码

分为 Better Auth 映射、安全策略和高风险 Challenge 三个区块。

Better Auth 区块展示登录 OTP、找回密码模板映射和适配器状态。明确说明用户、验证码验证和会话由 Better Auth 管理，首版仅允许已有账号登录；宿主配置必须省略 `signUpOnVerification`，不得传入 `false` 冒充禁用。

安全策略区块展示验证码长度、有效期、最大尝试次数、证明有效期、手机号发送间隔/小时/每日限制、IP 窗口限制、可选系统级 UTC 每日预算，以及人工熔断开关与原因。保存时携带策略 `version`；预算为空明确显示“不限制”，熔断开启时用常驻高优先级告警说明所有真实发送将被拒绝。降低安全阈值、提高发送上限、修改预算或切换熔断需要确认并展示影响；供应商配置与安全策略分别保存、分别处理版本冲突。

Challenge 区块说明证明绑定用户与动作、短时且单次使用；这里只展示或编辑相关策略，不提供查看 OTP 或证明值的入口。

### 4.5 回执与补查

展示回调连通状态、最近回调时间、最近批次、重复回执数量、无法关联的合法回执数量、待补查数量和最终未知数量。无法关联的数量突增应显示告警，但不展示回调中的完整手机号或原始载荷。

提供手动补查操作，必须选择时间范围或具体消息，展示预计处理数量，提交后显示任务 ID。页面只显示脱敏回调路径和配置状态；包含令牌的完整 URL 由宿主服务端部署工具生成并交给阿里云控制台，不通过浏览器 API 返回。页面提醒阿里云账号可能只有一个回调地址配置，且宿主代理日志必须屏蔽路径令牌。

### 4.6 发送记录

筛选条件：日期范围、模板键、用途、受理状态、送达状态和脱敏手机号查询。表格中受理状态与送达状态必须是两列，禁止合并为“成功”。

详情抽屉展示消息时间线、每次 Attempt、回执来源、稳定错误码、供应商 Request ID/BizId 和脱敏元数据。没有最终回执时显示等待或最终未知，不显示为失败。

### 4.7 统计

顶部指标卡：提交、受理、明确拒绝、受理未知、受理率、等待送达、已送达、送达率、送达失败和最终未知。趋势图支持按天查看；模板表支持按模板键和用途比较。

分母必须可见：受理率为受理数/提交数，送达率为送达数/受理数。前端直接消费 `submitted`、`accepted`、`acceptanceRejected`、`acceptanceUnknown`、`deliveryWaiting`、`delivered`、`deliveryFailed`、`deliveryUnknownFinal` 和 `retry` 等明确 DTO 字段，不自行从一个通用 `failed/unknown` 字段推导。时间范围内仍等待回执的数据单独展示，不能混入送达失败或最终未知。

## 5. 状态与反馈

全局状态使用以下语义：

- 正常：配置通过测试、存在可用资源、回调新鲜且无明显积压。
- 待配置：缺少引用、签名或模板。
- 待测试：配置发生变化后尚未重新测试。
- 降级：权限、云端资源、回调或任务积压存在问题，但部分能力仍可用。
- 已停用：管理员关闭全局发送。

Toast 只用于简短确认；需要行动的错误必须留在页面或表单中。后台任务使用可返回查看的任务状态，不用 Toast 假设任务已经完成。

## 6. 权限表现

前端权限动作与服务端保持一致：

- `config.read`、`config.write`
- `resource.sync`、`signature.manage`、`template.manage`
- `sms.test`
- `message.read`、`stats.read`
- `receipt.reconcile`

前端隐藏或禁用控件只改善体验，不替代服务端鉴权。禁用控件需要说明缺少的权限；服务端返回拒绝时展示通用错误，不泄露资源详情。

## 7. 无障碍与响应式

- 支持键盘访问所有标签、表格操作、对话框和详情抽屉。
- 对话框打开后聚焦标题或首个字段，关闭后把焦点归还触发按钮。
- 错误摘要使用 `aria-live` 或等价机制；状态徽标包含文本。
- 最小正文文字与背景满足 WCAG AA 对比要求。
- 桌面端表格优先；窄屏将次要列移入详情，不使用无法横向定位的超宽表格。
- 图表必须有可访问名称、数值摘要和等价数据表入口。

## 8. 组件边界

建议组件保持单一职责：

- `SmsAdminShell`：标题、状态和标签导航。
- `ProviderConfigForm`：配置字段与乐观锁冲突。
- `ConnectionTestPanel`、`TestSendDialog`：两阶段测试。
- `ResourceSyncPreview`：云端差异预览。
- `SignatureTable`、`TemplateTable`、`TemplateImportDialog`：资源管理。
- `VerificationSettings`：Better Auth 映射、Challenge、限流、预算和熔断策略。
- `ReceiptHealthPanel`、`ReconcileDialog`：回执与补查。
- `MessageFilters`、`MessageTable`、`MessageTimeline`：发送明细。
- `SmsMetricCards`、`DeliveryTrendChart`、`TemplateBreakdownTable`：统计。

组件不自行拼接供应商参数或解释供应商状态；统一使用服务端 DTO 和领域错误映射。

## 9. API 与 DTO 消费规则

- 所有请求以 `import type` 使用 `sms-kit/next/types` 导出的 DTO 和稳定错误码联合类型；不得在前端复制或另建含义相同但字段不同的类型，也不得把仅服务端的值导入 Client Component。
- 默认管理 API 前缀和端点见 PRD 第 11.1 节。宿主修改前缀时只修改请求客户端配置，不改变 DTO。
- 成功响应、分页响应和错误响应分别遵循 PRD 定义的 `{ data, requestId }`、`PageDto<T>` 和稳定错误结构。
- 开发模拟服务必须实现同一 TypeScript 接口并通过 DTO fixture 类型检查；禁止为方便页面开发自行发明字段。
- 写请求包含 `version` 与操作幂等键。收到并发冲突时重新读取，不自动重复写请求。

## 10. 测试与验收

- 单元测试覆盖格式化、状态徽标、权限分支和错误映射。
- 组件测试覆盖配置表单、差异预览、启停确认、真实发送确认和乐观锁冲突。
- 组件测试覆盖策略配置的安全确认、预算为空/触顶和熔断常驻告警，并验证供应商配置与策略配置的版本冲突互不覆盖。
- 交互测试覆盖键盘导航、焦点恢复和表单错误摘要。
- E2E 覆盖首次配置、权限测试、资源导入、模板启用、模拟发送、回执更新和统计一致性。
- 租户隔离测试使用两个虚构租户，确认相同业务幂等键可独立使用，且记录、精确手机号查询、任务与统计不会跨租户出现。
- 测试数据只使用虚构手机号和模拟 Provider，不把真实凭据或用户数据放入前端 fixture。
- 在最小 Next.js fixture 中验证服务端入口可构建、Client Component 导入敏感入口会构建失败，而 `sms-kit/next/types` 的纯类型导入可构建。
