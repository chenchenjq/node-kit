# sms-kit 管理端前端开发规范

## 1. 适用范围

本规范用于在 Next.js 宿主应用中实现 `sms-kit` 管理端。`sms-kit` 本身保持 headless，不导出 React 组件、样式或浏览器端 Secret 能力。

默认技术栈：

- Next.js App Router
- TypeScript strict
- Tailwind CSS
- shadcn/ui
- 宿主既有的表单、数据请求、通知和权限方案；如无既有方案，表单使用 React Hook Form 与 Zod

所有调用凭据解析器、阿里云 SDK、PostgreSQL 和管理写操作的代码必须位于 Node.js Runtime 服务端，不支持 Edge Runtime。客户端组件只能接收脱敏 DTO。

## 2. 信息架构

页面标题为“短信管理”，使用同一页面内的资源标签页：

1. 服务配置
2. 签名
3. 模板
4. 验证码
5. 回执与补查
6. 发送记录
7. 统计

页面标题区始终展示整体状态徽标、最近权限测试时间、最近回执时间和当前告警数量。用户无某标签权限时隐藏写操作，但保留必要的只读状态；完全无读取权限时显示明确的无权限页。

## 3. 通用交互规则

- 页面 URL 保存当前标签、页码、筛选和日期范围，刷新与分享后状态可恢复。
- 所有表格提供加载骨架、空状态、错误状态、重试入口和分页。
- 表单字段必须有持久标签、说明、错误文本和错误摘要；不能只依赖 placeholder。
- 写操作在成功后使相关查询失效，并展示可追踪的操作结果，不做乐观假成功。
- 使用服务端返回的 `version` 做乐观锁；冲突时展示“配置已被其他操作修改”，允许重新加载，不静默覆盖。
- 供应商错误转换为面向管理员的说明，并在详情中显示可复制的稳定错误码和 Request ID。
- 完整手机号、Secret、OTP、未过滤模板变量和供应商原始载荷不得进入客户端。
- 危险操作不得只靠颜色表达；按钮文本必须明确具体动作。

## 4. 标签页规范

### 4.1 服务配置

展示字段：供应商、区域、可选端点、AccessKey ID 引用、AccessKey Secret 引用、启用状态、最近测试摘要和版本。

主要操作：

- 保存配置。
- 执行无费用的连接与权限测试。
- 打开真实发送测试对话框。
- 启用或停用短信服务。

保存密钥引用后不回显完整引用；只展示 scheme 和脱敏变量名。配置发生变化后，状态回到“待测试”，只有权限测试成功才能启用。真实发送测试对话框必须展示脱敏手机号、签名、模板、变量名、费用提示和确认按钮。

### 4.2 签名

表格列：签名名称、云端类型、云端审核状态、本地启停、最近同步时间和关联模板数。

同步先展示差异预览：新增、状态变化、云端不可用和未选择导入的资源。管理员确认后才更新本地快照。停用有关联启用模板的签名时，展示影响模板数量并要求确认。

### 4.3 模板

表格列：稳定键、云端名称、TemplateCode 脱敏展示、用途、变量、签名、云端状态、本地状态和最近同步时间。

导入流程要求管理员：

1. 选择云端已审核模板。
2. 选择已导入签名。
3. 输入稳定模板键。
4. 指定用途。
5. 检查自动解析的变量集合。
6. 确认导入并决定是否立即启用。

稳定键保存后默认不可直接修改；修改需要单独操作、展示调用方影响提示并写入审计。

### 4.4 验证码

分为 Better Auth 映射与高风险 Challenge 两个区块。

Better Auth 区块展示登录 OTP、找回密码模板映射和适配器状态。明确说明用户、验证码验证和会话由 Better Auth 管理。

Challenge 区块展示验证码长度、有效期、最大尝试次数、证明有效期和默认限流规则。安全默认值变化需要确认，并展示可能影响。

### 4.5 回执与补查

展示回调连通状态、最近回调时间、最近批次、重复回执数量、待补查数量和最终未知数量。

提供手动补查操作，必须选择时间范围或具体消息，展示预计处理数量，提交后显示任务 ID。回调 URL 可复制，但页面提醒阿里云账号可能只有一个回调地址配置。

### 4.6 发送记录

筛选条件：日期范围、模板键、用途、受理状态、送达状态和脱敏手机号查询。表格中受理状态与送达状态必须是两列，禁止合并为“成功”。

详情抽屉展示消息时间线、每次 Attempt、回执来源、稳定错误码、供应商 Request ID/BizId 和脱敏元数据。没有最终回执时显示等待或最终未知，不显示为失败。

### 4.7 统计

顶部指标卡：提交、受理、受理率、送达、送达率、最终失败、最终未知。趋势图支持按天查看；模板表支持按模板键和用途比较。

分母必须可见：受理率为受理数/提交数，送达率为送达数/受理数。时间范围内仍等待回执的数据单独展示，不能混入最终失败。

## 5. 状态与反馈

全局状态使用以下语义：

- 正常：配置通过测试、存在可用资源、回调新鲜且无明显积压。
- 待配置：缺少引用、签名或模板。
- 待测试：配置发生变化后尚未重新测试。
- 降级：权限、云端资源、回调或任务积压存在问题，但部分能力仍可用。
- 已停用：管理员关闭全局发送。

Toast 只用于简短确认；需要行动的错误必须留在页面或表单中。后台任务使用可返回查看的任务状态，不用 Toast 假设任务已经完成。

## 6. 权限表现

前端权限动作与服务端保持一致：

- `config.read`、`config.write`
- `resource.sync`、`signature.manage`、`template.manage`
- `sms.test`
- `message.read`、`stats.read`
- `receipt.reconcile`

前端隐藏或禁用控件只改善体验，不替代服务端鉴权。禁用控件需要说明缺少的权限；服务端返回拒绝时展示通用错误，不泄露资源详情。

## 7. 无障碍与响应式

- 支持键盘访问所有标签、表格操作、对话框和详情抽屉。
- 对话框打开后聚焦标题或首个字段，关闭后把焦点归还触发按钮。
- 错误摘要使用 `aria-live` 或等价机制；状态徽标包含文本。
- 最小正文文字与背景满足 WCAG AA 对比要求。
- 桌面端表格优先；窄屏将次要列移入详情，不使用无法横向定位的超宽表格。
- 图表必须有可访问名称、数值摘要和等价数据表入口。

## 8. 组件边界

建议组件保持单一职责：

- `SmsAdminShell`：标题、状态和标签导航。
- `ProviderConfigForm`：配置字段与乐观锁冲突。
- `ConnectionTestPanel`、`TestSendDialog`：两阶段测试。
- `ResourceSyncPreview`：云端差异预览。
- `SignatureTable`、`TemplateTable`、`TemplateImportDialog`：资源管理。
- `VerificationSettings`：Better Auth 映射和 Challenge 参数。
- `ReceiptHealthPanel`、`ReconcileDialog`：回执与补查。
- `MessageFilters`、`MessageTable`、`MessageTimeline`：发送明细。
- `SmsMetricCards`、`DeliveryTrendChart`、`TemplateBreakdownTable`：统计。

组件不自行拼接供应商参数或解释供应商状态；统一使用服务端 DTO 和领域错误映射。

## 9. 测试与验收

- 单元测试覆盖格式化、状态徽标、权限分支和错误映射。
- 组件测试覆盖配置表单、差异预览、启停确认、真实发送确认和乐观锁冲突。
- 交互测试覆盖键盘导航、焦点恢复和表单错误摘要。
- E2E 覆盖首次配置、权限测试、资源导入、模板启用、模拟发送、回执更新和统计一致性。
- 测试数据只使用虚构手机号和模拟 Provider，不把真实凭据或用户数据放入前端 fixture。
