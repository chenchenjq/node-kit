# Domain Docs

Engineering skills should use the repository's multi-context domain documentation.

## Before exploring

- Read `CONTEXT-MAP.md` at the repository root and then the `CONTEXT.md` for each context relevant to the task.
- Read system-wide decisions in `docs/adr/` and context-specific decisions in the relevant package's `docs/adr/` directory.
- If a referenced context or ADR file does not exist, proceed without flagging its absence; create it when a domain term or decision is actually resolved.

## Vocabulary and conflicts

Use terms as defined by the relevant context document. If a proposed change contradicts an existing ADR, identify the ADR explicitly and explain why it may need to be reopened.
